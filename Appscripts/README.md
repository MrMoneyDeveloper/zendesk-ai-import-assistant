# Appscripts Workspace

This folder contains the full Google Apps Script and local tooling layer for the Sheets-first phase.

## Goals

- Keep all Apps Script code and automation assets in one tracked place.
- Provide a one-time setup path for sheets/templates/folders.
- Sync FastAPI schema contracts into Apps Script.
- Run row-level validation in Apps Script.
- Expose a secured Apps Script web API for backend integration.

## Structure

- `src/`: Apps Script source (`.gs`) and `appsscript.json` manifest.
- `tools/`: local scripts for schema export, template generation, and secret bootstrap.
- `contracts/`: generated JSON contracts from FastAPI/Pydantic models.
- `templates/`: generated Excel template file.
- `secrets/`: local-only runtime secrets (gitignored except `.gitkeep`).
- `.env`: tracked placeholder defaults.
- `.env.local`: local secret overrides generated by tooling (gitignored).

## Setup flow

1. Generate backend schema bundle:
   - `python Appscripts/tools/sync_fastapi_schemas.py`
2. Generate local API key + env snippet:
   - `python Appscripts/tools/generate_local_secret.py`
3. Generate/update Excel template:
   - `python Appscripts/tools/generate_excel_template.py`
4. Create a standalone Apps Script project and set the Script ID in `Appscripts/.clasp.json`.
5. Push sources:
   - `cd Appscripts`
   - `npx @google/clasp push`
6. In Apps Script editor, run `setApiKeyFromEditor('<your_key>')` once.
7. Deploy Web App and copy `/exec` URL into backend `.env` as `APPS_SCRIPT_WEB_APP_URL`.
8. Call from backend API endpoints (added under `/api/import-assistant/appscript/*`).

## Operating-model upgrade

The department-first backend requires `OperatingModel.gs` plus the updated `Config.gs`, `Utils.gs`,
`SheetWriter.gs`, `Validation.gs`, and `Api.gs`. After pushing these files, run `setupOnce({})` once and
deploy a new Web App version. The migration appends missing headers and creates dedicated tabs for Brands,
Groups, Automations, Categories, Sections, Articles, Batch Metadata, and Progress Log.

Upgrade commands:
- `cd Appscripts`
- `npx @google/clasp login` (only when `clasp` reports `invalid_grant` or `invalid_rapt`)
- `npx @google/clasp push`
- In Apps Script, run `setupOnce({})`, then edit the Web App deployment and select **New version**.

The combined staging response now includes `summary.timings_ms` for staging, validation, preview, and total
Apps Script time. Approval writes independently force failed or blocked records back to `blocked`, and
execution summaries count only the latest result for each record.

Batch staging is idempotent by `batch_id` and `record_id`, so retrying a run replaces that batch's prior
object rows instead of duplicating them. Progress events and batch metadata use upsert keys and are safe to
send more than once.

For projects maintained by copying files in the Apps Script editor instead of `clasp`, follow the
copy-safe checklist in `Appscripts/manual-install/README.md`.

Manual editor helper:
- `rotateApiKeyFromEditor()` generates a fresh key, stores it in Script Properties, and writes it to the `Integration Secrets` sheet.

## Security

- API access is guarded by `APPS_SCRIPT_API_KEY` stored in Script Properties.
- Never commit real keys in this repo.
- Local key files are written to `Appscripts/secrets/` and ignored by git.
- Local env secrets are written to `Appscripts/.env.local` and ignored by git.

## Backend env mapping

Add or update these in `backend/.env`:

- `APPS_SCRIPT_WEB_APP_URL=`
- `APPS_SCRIPT_API_KEY=`
- `APPS_SCRIPT_TIMEOUT_SECONDS=20`

## Notes

- Apps Script does not reliably expose custom incoming headers for web apps, so API key auth is carried in JSON body (`api_key`) for POST calls and query param for privileged GET calls.
- `doGet?action=health` is intentionally open for basic liveness checks.
